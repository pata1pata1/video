# 制作の手順（決定版）と完成形の知識

- 作成：2026-11-23（Mac、案件 `an`）。ユーザーに「今日は一番上手にできた。今日のやり方を記憶しておきましょう」と言われた流れを、Mac と Windows の両方の Claude が同じように使えるように書いたもの
- 対象：横長のトーク動画（talk-subtitle）。コマンドの詳しい使い方は `../CLAUDE.md`、仕組みは `design.md`

## 1. 手順

1. **準備**
   - 元動画は `projects/<id>/input/` に置く
   - ユーザーがフォルダを手で作って `npm run new` が使えない場合は、同じ中身を補う。補うのは `project.json`、`audio/` `intermediate/` `review/` `output/` の空のフォルダ、`_shared/project-template` の2ファイル。動画には触らない
   - スマホの動画には回転情報が付くことがある。回転情報があれば、1コマ取り出して頭が上になっているかを確かめる
2. **固有名詞**
   - 読みと一緒に教えてもらい、案件の辞書と共通辞書（`--shared`）の**両方**に登録する（ユーザーの希望）
   - 間違えて文字になりやすい形（`--misrecognition`）も付ける
   - 普通の言葉でもある名前（例：アイリス → あいり）には `--name-context-only` を付ける
3. **カット候補**
   - phase1 の自動の候補に、Claude が全文を読んで見つけた言い直し・言いかけを `candidates --add-claude` で足す。言い直しは先の方を削り、後の方を残す
   - **切る位置は文字起こしの時刻で決めない**。whisper の単語の時刻は、無音に伸びたり数秒ずれたりする。音量（50ms〜10ms ごとの RMS）で、声が切れているところを探して決める
   - つなぎ目の前後をつないだ音声を書き出して文字起こしし、言葉が途中で切れていないか、余分な音（「あ」など）が残っていないかを確かめる
4. **プレビューを見せる前に**
   - 1秒以上の無音が残っていないかを確かめる（ツールが音量からも候補を出すようになった）
   - プレビュー全体を文字起こしし直して、重なった言いかけが残っていないかを確かめる
   - プレビューは音量を整えていないので、完成版で整うと一言添える
5. **ユーザーの指摘**
   - ユーザーが言う時刻はプレビュー上の秒。`intermediate/timemap.json` で元動画の秒に直す
   - 直したら、同じ種類の漏れを全体から探す
   - ツールで拾えるものは `src/candidates.ts` にルールを足し、`design.md` と `CLAUDE.md` に書いて commit する（学習）
6. **字幕**
   - `cut --final` の後に作る。自動の字幕案（draft）は時刻と文字が不正確なので、そのまま使わない
   - 時刻は `npm run subtitles -- retime` で合わせる（下の2章）
   - 名前・聞き間違い（例：精神 → 精子）・数字（例：3123円 → 3万123円）を直す
   - 長い字幕は、静止画（`subtitle-stills`）で1行に収まるかを確かめる
   - 文字起こしし直すと、残っている言い直しが見つかることがある。見つけたらユーザーに確認して削る
7. **書き出し**
   - 字幕の承認の後に `render` を実行する。音量は -14 LUFS で、ピークを先に抑える（`design.md` の14.3）。音量は Claude が決めてよいとユーザーから任されている
   - チェックで止まったら原因を突き止めてツールを直し、`render --check-only` でチェックだけやり直す
   - 完成したら1コマ取り出して目で確かめ、`style observe` で学習データに記録する
8. **小さな問題**：残った小さな問題（例：音声が 5ms 遅れた）は隠さずに伝え、作り直すかはユーザーに選んでもらう
9. **公開の後**：公開の URL をもらったら、remotion で `video:mark-completed` と `video:mark-published` を実行して記録する。完成した MP4 は、今の方針では消さない

## 2. 字幕の時刻の合わせ方

whisper の単語・トークンの時刻で字幕を付けると、声と字幕がずれる。an では、最初の字幕が遅く、ほかは早すぎる所が多かった。whisper.cpp の `--dtw` も、時刻が出なかった。

**`npm run subtitles -- retime --project=<id>` で合わせる**（2026-11-23 にコマンドにした。Mac と Windows で同じ結果になる）。

- **使う順番**：`cut --final` → `subtitles draft` → 字幕の分け方と表記を直す（edit・edit-batch。約13文字の意味のまとまり）→ `subtitles retime --dry-run` で変わる時刻を見る → `subtitles retime` → 確認画面・静止画 → approve
- **中でやっていること**
  1. `cut.mp4` の音声（16kHz・モノラル）で、10ms ごとの音量を測る。声とみなす音量（既定は自動。大きいほうから5%の音量 −25dB を、-55〜-35dB の範囲に収める。an では -45dB 前後）を超えるところを声とし、0.2秒未満の切れ目はつないで「声のかたまり」にする（an では約110個）
  2. かたまりごとに文字起こしする。共通エンジンの `transcribeClipsWithBackend` を使い、モデルの読み込みは1回だけ。Mac は whisper.cpp、Windows は faster-whisper（`python/fw_transcribe.py --clips`）。「ご視聴ありがとうございました」のような、無音から作られた文は捨てる
  3. 字幕の文字と聞こえた文字を、最長共通部分列で対応させる。カタカナとひらがな、全角と半角はそろえて比べる
  4. 字幕の始まりは、最初の文字が聞こえた時刻にする。かたまりの途中で始まる字幕は、近く（±0.5秒）の息つぎ（声の音量 +7dB より小さい所）にそろえる
  5. 字幕の終わりは、次の字幕まで0.7秒未満なら次の字幕まで出し、それより長いときは0.3秒だけ残して消す
- **出す警告**
  - 声との対応が60%未満の字幕：聞き間違いか、字幕の文字が声と違うか、カットの漏れ
  - 0.4秒未満の字幕
  - **字幕に無い声**：言い直しの残りの手がかり。つなぎの言葉（はい・うん・まあ など）は省く。字幕の書き始めや終わりの表記違いが混ざることもある
- **かかる時間**：an（3分40秒・110個）の Mac で約3.5分
- **設定**：`input/settings.json` の `retime`（`voiceDb`・`breathDb`・`joinGapSeconds`・`snapSeconds`・`holdGapSeconds`・`tailSeconds`・`hallucinations`）。既定値は `src/config.ts`
- **Windows**：faster-whisper の `--clips` モードは、まだ Windows で動かしていない。最初の Windows の案件で `--dry-run` から確かめる

## 3. 完成形（ユーザーが書き出しの後に足すもの）

an（https://youtu.be/eX9K6e1uJew）は、Claude の `final.mp4`（カット・字幕・明るさ・-14 LUFS）を元にユーザーが仕上げて公開した。長さ・カット・字幕は Claude の書き出しのままだった（字幕は1つも直されていない）。ユーザーの希望は「いつかは完成形まで仕上げられるように」。

- **話題に合わせた画像（一番大きな違い）**
  - ほぼ全編で、画面の右側（幅の半分くらい）に画像が出ている。話している人は左に残し、顔と字幕は隠さない
  - 新しい名前や話題を言い始める字幕のところで切り替わり、1枚あたり約6〜25秒出す
  - 中身は次のとおり
    - X の投稿のスクリーンショット（本人の告発・振込明細・関係者や暴露系インフルエンサーの投稿・会社の声明）。いいね数などの枠ごと切り抜く
    - 名前が出た人の写真（顔のアップや、番組に出ている場面）
    - お店や番組の宣伝画像、告発文の画像
- **BGM**：DOVA-SYNDROME の曲を、最初から最後まで、声より約20〜25dB 小さく入れる。今のツールでも、`input/bgm/` に曲を置けば同じ形にできる（`bgmBelowVoiceDb` の既定は 20）
- **サムネイル**：赤と黒の背景に、番組ロゴ、人物3人（中央に話題の中心の人）、名前の帯、黄色の極太の文字の見出し（例：「在籍店がヤバすぎ!!」）
- **タイトル**：【界隈名】＋あおる見出し＋「！」で区切った要点。例：「【溝口界隈】ラストコール出演キャバ嬢の在籍店がヤバすぎる！給料没収！セクハラ黒服！」
- **概要欄**：決まった型（■SNS・サービス／■スポンサーサイト／■BGM の出典）に、ハッシュタグ3つ（番組名・業界・中心の人）

画像を入れる機能はまだツールにない（未実装の Phase 4）。作るときは、この形を最初の案にする。X の投稿や人物の写真は、ユーザーが用意するか、出典と使ってよいかを確かめてから使う。

## 4. この日にツールに足したもの（コードは Git にある）

- カット候補：音量だけで見つけた1秒以上の無音も出す（`audioQuietMinSeconds`）。短い言いかけの後に長い間があるところを確認候補にする
- 書き出し：ピークを先に抑えてから -14 LUFS にする（共通エンジンの `limitPeaksTowardLoudness`。遅れの補正あり）
- 書き出し：区間に分けて書き出すときの境目を、`cut.mp4` の実際のフレームの位置にする。フレーム数は、実際に取り出せるフレームで比べる。`render --check-only` を足した
- 共通辞書：an の名前（アンジュール東京・鈴音りん・あいり・角田・林尚宏・溝口勇児・オロチ美琴・神谷朱音・エンターテイナー折原）

## 5. Git で共有しないもの

- `projects/`（元動画・文字起こし）と `style-data/`（学習の観察データ）は、実案件の発話や人名を含むので、方針として Git に入れない。an の観察データ（`style-data/observations/an.json`）は Mac にだけある
